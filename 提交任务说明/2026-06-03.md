## 🏗️ 1. 购物车微服务核心架构与双写逻辑实现 (`o2o-cart-service`)

为了解耦用户服务并支撑高吞吐、低延迟的购物车操作，系统独立搭建了 `o2o-cart-service` 微服务（端口 `8085`），并实现了基于 **MySQL (数据持久底盘) + Redis (高并发 Hash 极速读) 同步双写架构**：
*   **物理幂等性保证**：在 `tb_cart` 购物车表中设计了 `uni_user_goods(user_id, goods_id)` 联合唯一索引。该设计在数据库底盘强制约束了商品项的唯一性，拦截了高并发重试引发的重复加购，从物理层保障了幂等。
*   **Redis 双写数量**：购物车采用 Redis Hash 结构（`o2o:cart:{userId}`）进行数量存储，商品加购采用 Redis 原生 `HINCRBY` 命令累加，保障高并发下的原子操作，读请求直接由 Redis 极速响应。
*   **Feign 异步详情装配**：购物车仅存储商品 ID 与数量。在拉取购物车列表 (`getCartList`) 时，提取全部商品 ID 列表，通过 Feign 跨服务调用商品微服务 (`o2o-shop-service`) 批量获取最新商品详情（名称、实时单价、图片、状态等），在内存中动态组装为 `CartVo`，确保价格和上下架状态绝对实时。

## 🔄 2. 购物车勾选状态与下单批量清理联动 (`o2o-api`)

为了支持下单结算链路并降低网络 I/O 损耗，实现了多端联动的高效批量清理机制：
*   **勾选状态 Set 独立管理**：通过独立的 Redis Set（`o2o:cart:selected:{userId}`）存储用户当前勾选中的商品 ID，相较于 Hash 存 JSON 的方案，既保留了数量修改的 `HINCRBY` 原子自增特性，又支持通过 `SMEMBERS` 快速取得选中集合。
*   **Feign RPC 选中清单导出**：在 `o2o-api` 声明了 `CartClient` 远程接口，允许交易服务 (`o2o-trade-service`) 结算下单时拉取被勾选结算且有效的商品详情。
*   **下单批量清理一次性 I/O 释放**：在 `CartService` 和 `CartClient` 中实现了 `deleteCartItems` 接口。交易服务下单支付成功后，可跨服务 RPC 批量删除对应的已购商品，利用 `opsForHash().delete` 和 `opsForSet().remove` 可变参数特性，在 Redis 层面 1 次网络交互完成清理，并在 MySQL 中执行 `IN` 条件物理删除。

## ⚡ 3. 事务同步缓存更新与一键清理失效商品

为解决双写中“写缓存成功但写 MySQL 事务回滚”导致的弱一致性隐患，并丰富用户清理体验，实现了以下两个优化特性：
*   **事务成功提交后写缓存（`Transaction-Bound`）**：重构了所有写逻辑，引入 Spring 的 `TransactionSynchronizationManager` 注册事务同步钩子。将所有 Redis 写/删命令挂载在数据库事务完全 Commit 成功后（`afterCommit` 阶段）执行。当数据库回滚时，Redis 不会发生脏写入，保证了缓存与数据库的最终强一致。
*   **一键清理失效/下架商品 (`clearExpiredItems`)**：暴露了 `DELETE /cart/clear/expired` 控制层接口。系统拉取购物车内所有的商品 ID，使用 Feign 批量查询商品最新状态，在内存中交叉比对，将下架（`status = 0`）或已不存在的商品一键通过批量删除逻辑物理洗净。

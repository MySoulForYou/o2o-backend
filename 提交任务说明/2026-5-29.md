# 📝 2026-05-29 提交任务说明

本项目阶段性工作已全部完成。本篇文档对这一周期内完成的店铺与商品微服务（`o2o-shop-service`）架构重构、防横向越权校验机制设计、Springdoc 接口文档集成、数据库结构升级以及网关分流规则还原工作进行总结归档。

---

## 🏗️ 1. 店铺商品微服务架构解耦与重构 (`o2o-shop-service`)
*   **单一微服务还原**：为了防止微服务“模块爆炸”及系统臃肿，我们将原先物理解耦拆分的 `portal`（客户端）与 `admin`（商家端）模块合并还原为单一微服务 `o2o-shop-service`（端口 `8082`），保障了微服务工程的统一性与低维护开销。
*   **逻辑分包物理解耦（RuoYi-Cloud风格）**：采用包路径对业务进行逻辑解耦，在代码目录中隔离出 `customer`（消费者只读端）与 `merchant`（商家端写与管理）两个子包，接口路由分别映射为 `/shop/customer/**` 和 `/shop/merchant/**`。
*   **API 文档自动化集成**：集成了 `springdoc-openapi-starter-webmvc-ui` (版本 `2.5.0`)，自动生成符合 OpenAPI 3.0 规范的 JSON 接口文档，支持在 Apifox 中一键同步与调试。

## 🛡️ 2. B 端商家行级安全与防越权校验机制
*   **防横向越权（IDOR）控制**：在商家端商品上架 Service 层实现了严格的安全防盗机制。通过 `UserContext.getUserId()` 获取网关提取并透传的当前登录商家 ID：
    *   *未指定店铺 ID*：自动反查该商家名下的唯一店铺并进行静默填充绑定，防止挂靠。
    *   *指定店铺 ID*：查库校验店铺所有者 `owner_id` 是否等于当前登录用户，一旦不匹配（横向越权攻击）直接中断事务并抛出 `403` 异常阻断。

## 🗄️ 3. 数据库与数据访问层对齐 (`o2o_shop_db`)
*   **所有权字段新增**：在 `tb_shop`（店铺表）中物理添加了 `owner_id` 属性，建立起了“商家 ➡️ 店铺 ➡️ 商品”的数据库关联纽带，并在本地 MySQL 中为现存 Mock 店铺归属权数据进行了初始化配置。
*   **数据实体与映射更新**：更新了 `Shop.java` 实体类加入 `ownerId`，并对齐了 `ShopMapper`、`GoodsMapper`、`ReviewMapper` 基础数据操作接口。
*   **拦截器注册**：新增了店铺微服务的 `WebMvcConfig` 并挂载 `UserContextInterceptor`，实现当前请求 `X-User-Id` 的自动获取、使用与线程安全清理。

## 🔀 4. 网关分流路由简化还原 (`o2o-gateway`)
*   **路由规则简化**：将网关路由表中的复杂拆分路由还原为单路 `/api/shop/**` 并剥离前缀（`StripPrefix=1`）转发至 `lb://o2o-shop-service` 的极简路由规则，降低了网关的转发负担和后续运维复杂度。

## 📄 5. 系统设计文档同步更新 (`docs`)
*   **数据库表设计同步**：同步更新了 `docs/o2o-backend_数据库表设计.md`，增补了 `tb_shop.owner_id` 字段的 DDL 建表 SQL 及其防御横向越权的字段设计考量逻辑。
*   **商铺域细节总结**：更新并完成 `docs/设计细节说明/shop层_核心业务细节总结.md`，归档了“物理微服务拆分 vs 内部逻辑分包”以及“JWT 载荷 vs 实时查库/Redis 校验”的两大核心技术方案比对和架构设计记录。
